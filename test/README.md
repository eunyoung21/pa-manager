# 계약서 양식(.docx) 채우기 — 검증

계약서 문구가 바뀌면 코드를 고치는 대신 앱에서 새 양식을 올린다.
그 동작이 깨지지 않았는지 확인하는 두 가지 테스트.

빈 양식(.docx) 2개와 이미 채워진 계약서 1개가 필요하다.
(예: `D:\Downloads\광고모델계약서 양식 - 드래프터 (수정) (3).docx`)

## 1) 엔진 테스트 — index.html 안의 엔진을 그대로 실행

```
node test/contract-template.test.mjs index.html 빈양식1.docx 빈양식2.docx 채워진계약서.docx
```

확인 항목: 값 반영(이름·모델료·계약일자·연락처·주민번호·주소), 조항 본문 보존,
광고주 칸 미침범, 파트 14개 보존, `{{표시자}}` 치환(워드가 조각낸 경우 포함),
이미 채워진 칸 덮어쓰기 금지.

## 2) E2E — 실제 크롬으로 앱을 띄워 클릭

```
node test/contract-template.e2e.mjs 빈양식.docx
```

목 백엔드(get/save/pfileSave/pfileGet)를 띄우고 index.html 을 그대로 로드한 뒤
`📄 계약서 생성` → `양식 올리기` → 값 입력 → `내려받기` 까지 실제로 눌러
내려받은 .docx 내용을 검사한다. 새로고침 후 다른 접속에서도 같은 양식이 쓰이는지(pfileGet)까지 확인.
크롬 경로는 스크립트 상단 `CHROME` 상수.

## 3) 메일 발송 — 백엔드 로직

```
node test/contract-mail.test.mjs
```

`apps-script/Code.gs` 를 그대로 읽어 구글 전역(GmailApp·Utilities…)만 가짜로 끼워 `contractMail` 을 실행한다.
확인 항목: 첨부 바이트 보존, 수신자·제목·본문 전달, 회신주소·발신 별칭·사본(cc) 규칙,
잘못된 이메일/첨부 거부, 파일명·제목 방어(헤더 인젝션), 일일 한도·발송 실패 처리.

## 4) 메일 발송 — E2E (실제 크롬)

```
node test/contract-mail.e2e.mjs [빈양식.docx]
```

목 백엔드가 `contractMail` 요청을 받아 보관하고, 앱에서 값 입력 → `📧 메일 보내기` 한 번으로
받는 사람·자동 작성된 제목/본문·첨부(.docx)가 다 실려 오는지 확인한다.
첨부는 실제로 풀어서 계약서 값(이름·모델료·계약일자·연락처)이 들어있는지까지 본다.
발송 실패 시 폴백(파일 다운로드 + Gmail 작성창)도 검사. 양식 인자를 주면 업로드 양식 경로도 함께 검사.

## 4) 자동화 탭 메모 보존

```
node test/automation-memo.test.mjs
```

알바가 🤖 자동화 탭에 남긴 메모가 로드 정규화에서 지워지지 않는지 확인.
(2026-08-21: `clearMemo` 가 매 로드마다 메모를 비워 계속 사라지던 문제 재발방지)

## 긴 표 점진 렌더 — 안 그려진 행이 빠지지 않는가

```
node test/progressive.e2e.mjs
```

표는 처음 60행만 그리고 스크롤하면 이어 붙는다(`useProgressive`).
눈에 안 보이는 행이 몰래 빠지면 삭제·정산이 어긋나므로,
① 상단 개수는 전체 기준 ② '전체 선택'은 걸러진 전체 행 ③ 검색은 아직 안 그린 행도 찾는다
④ 검색을 지우면 다시 처음 묶음부터 — 를 300행짜리 목데이터로 못 박는다. 인자 없이 실행.

## 5) 영상검수 광고코드가 저장 뒤에도 남는가

```
node test/review-code.e2e.mjs                       # 기본 흐름(입력·새로고침·스크롤 아래 행·연속 입력)
node test/review-code-conflict.e2e.mjs              # ★ 동시편집 충돌 중 입력 (PA_SLOW=1 이면 폴링까지, 4분)
node test/review-code-live.e2e.mjs <라이브스냅샷.json>  # 실제 운영 데이터 그대로 물려서
```

2026-09-01 사고 재발방지. 관리자가 영상검수에 광고코드를 줄줄이 넣는 동안 알바가 저장하면
내 저장이 `conflict` 로 돌아오고, 앱이 서버 최신본을 다시 받는 몇 초(앱스스크립트) 사이에 친
광고코드가 화면·서버 양쪽에서 사라졌다. 원인 두 가지를 각각 못 박는다.

- 병합 기준이 "요청 보낼 때의 화면" 스냅샷이라 그 사이 입력이 병합 결과에서 빠졌다
  → `pullMerge` 는 mine·base 를 **응답 도착 후에** 읽는다(함수로 전달).
- 서버본을 화면에 적용한 뒤 5초 동안은 내용이 달라도 자동저장을 통째로 건너뛰었다
  → 내용이 같을 때만 생략한다.
